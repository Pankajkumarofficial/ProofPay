# Deploying ProofPay

**Live: <https://proofpay-otbd.onrender.com>** — free plan, Singapore. The
`-otbd` is the suffix Render appends to make the hostname unique, so the URL is
never the service name verbatim and `render.yaml` keeps the plain name.

One service serves both halves. The browser calls `/api` as a relative path and
the session is a `sameSite: 'lax'` cookie, so splitting the API and the interface
across two origins would sign every request out. `createApp()` serves
`frontend/dist` whenever that directory exists, and the build below produces it.

---

## Before you touch Render

**1. MongoDB Atlas must allow `0.0.0.0/0`.**

A free Render service has no static outbound IP, so an allowlist of specific
addresses works until the first restart and then refuses every connection — as a
timeout, not as a permissions error, which is why it reads like the database is
down. Atlas → Network Access → Add IP Address → Allow access from anywhere.

**2. Uploaded evidence needs no disk — but it needs database room.**

Uploads are stored in MongoDB beside the Evidence record that owns them, so they
survive redeploys, restarts and the idle sleep on the free plan. Nothing is
written to the filesystem, which is ephemeral here and used to swallow every
file filed against a promise while the record describing it survived.

The cost is Atlas quota rather than a disk: the free tier is 512MB, and
`MAX_UPLOAD_MB` (10 by default) caps a single artefact. Withdrawn proof takes
its bytes with it. If the demo world gets heavy, lower `MAX_UPLOAD_MB` before
raising the plan.

## Deploy

1. Push this repo to GitHub.
2. Render → **New** → **Blueprint** → pick the repo. It reads `render.yaml`.
3. Fill in the variables marked "set in dashboard":

   | Variable | Value |
   |---|---|
   | `MONGODB_URI` | the Atlas connection string, with the password |
   | `AI_API_KEY` | your gateway or vendor key — leave empty to run the deterministic engine |
   | `AI_BASE_URL` | `https://integrate.api.nvidia.com/v1` for the current gateway |
   | `AI_MODEL` | required whenever `AI_BASE_URL` is set |

   `JWT_SECRET` is generated by Render. Don't set `CLIENT_URL` — `env.js` falls
   back to Render's own `RENDER_EXTERNAL_URL`, so the service does not need to
   know its address before it has one. It is where every completed sign-in is
   sent and where emailed links point, so production refuses to boot if it
   resolves to `localhost`: that would hand each visitor to their own machine at
   the last hop, after everything else had worked.

4. Wait for the deploy, then open <https://proofpay-otbd.onrender.com/api/health>.
   It reports the live Proof Engine, the payment mode and the payout rail.

## After the first deploy

**Google sign-in** needs the new origin registered, or the button 400s:

- Google Cloud Console → Credentials → your OAuth client
- Authorised JavaScript origins: `https://proofpay-otbd.onrender.com`
- Authorised redirect URIs: `https://proofpay-otbd.onrender.com/api/auth/google/callback`

Then set `GOOGLE_CLIENT_ID` and `GOOGLE_CLIENT_SECRET` in Render. Until both are
set the app simply does not offer Google sign-in, which is a working state — 
email and password are unaffected.

**Leave `GOOGLE_CALLBACK_URL` unset.** `env.js` derives it from
`RENDER_EXTERNAL_URL`, exactly as it does `CLIENT_URL`. Setting it to the
localhost value from `.env.example` does not break sign-in in a way you would
notice from the server: it breaks it in the *visitor's* browser, by sending them
to port 5050 on their own machine. Anyone running ProofPay locally is then
signed into their own copy by a button on the live site, and everyone else gets
a dead tab. Production now refuses to boot in that state, and the boot log names
the redirect URI it will send to Google:

```
Google sign-in: on, redirecting to https://proofpay-otbd.onrender.com/api/auth/google/callback
```

That string and the one in the Google Cloud Console have to match character for
character, or Google answers `redirect_uri_mismatch`.

**Seed the demo world**, so Judge Mode has something to walk through. Render
Shell (paid) or locally against the same Atlas URI:

```bash
MONGODB_URI="<the Atlas string>" npm run seed
```

## The free tier sleeps. Warm it before anyone judges it.

After 15 minutes without traffic Render stops the service. The next request
starts it again, which takes roughly **50 seconds** — a judge clicking your link
sees a blank tab for most of a minute and may well close it.

There is no setting for this on the free plan. What works:

```bash
# A few minutes before the demo, and again if it has been idle since:
curl https://proofpay-otbd.onrender.com/api/health
```

Wait for it to answer, then open the app. If judging is unattended — a link
submitted for someone to open whenever they like — the free plan is the wrong
choice and `plan: starter` is the fix.

## Checks worth running against the deployed URL

```bash
BASE=https://proofpay-otbd.onrender.com

curl -s $BASE/api/health                      # engine, payment mode, payout rail
curl -s -o /dev/null -w '%{http_code}\n' $BASE/promises/anything   # 200: deep links resolve
curl -s $BASE/api/nope                        # a JSON 404, not the page
```

The middle one is the one that catches a broken deployment: if a deep link
returns 404 rather than 200, the interface was not built or not found, and the
service is serving an API with no front end.
